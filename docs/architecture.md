# Architecture
The modular monolith separates devices/authentication, QR event/token orchestration, YEDAM referral, public support, optional surveys, minimal interactions, immutable audit, and removable demo adapters. Views validate transport concerns; `EventService` owns transactional lifecycle rules; framework-neutral JSON Schema contracts and clients are outward-facing ports. Modules call explicit services rather than another module's tables for business decisions.

Trust boundaries are device bearer authentication, public opaque URLs, authenticated/MFA admin, and database/cache infrastructure. General QR is a build/generated static asset and remains visible while an HMAC-SHA-256 dynamic token is prepared. The domain-separated message is `sentra-qr|1|device|event`; base64url output is 256 unpredictable bits. Only SHA-256 lookup hashes and key versions persist. Rotate by adding a new environment key/version, retaining old keys until mappings expire, then destroy retired keys.

Dynamic state is never restored to a display after restart. PostgreSQL is authoritative for partial uniqueness and row locks; SQLite supports local tests with reduced concurrency fidelity. The Python client owns a bounded technical retry queue concept; this release retries in memory and intentionally persists no outbox or sensitive payload. Future hosts send only contract fields server-to-server; the web controller never carries credentials.
